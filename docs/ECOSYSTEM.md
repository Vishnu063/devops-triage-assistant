# Reusable ecosystem diagnostics and verification

Triage remains independently usable with no model, paid API or cluster requirement. Ops Pilot already imports the existing `ExperienceEngine`, `ToolEngine`, native adapters, IncidentStore, persisted approvals and health probes. This change extends those components, not a second remediation implementation.

`triage.ecosystem.diagnosis(report)` accepts an existing structured ExperienceEngine incident report. It emits a version 1 Diagnosis with references to the supplied finding evidence, rule-based hypotheses and explicit uncertainty. It applies existing redaction and never executes commands. Its empty `suggested_commands` is intentional: the library does not manufacture shell commands from diagnostic prose. Existing native collector recipes retain their exact configured targets; existing next-step explanations remain advisory.

`triage.ecosystem.k8sgpt(adapter, enabled=False)` is disabled by default. With an explicit Kubernetes ToolAdapter and `enabled=True`, it calls `k8sgpt analyze --kubecontext <context> --namespace <namespace> --output json` through the existing timeout/output-bounded native transport. No `--explain`, model/backend configuration, arbitrary command text or mutation is introduced. It stores only bounded finding kind/name metadata, not raw diagnostic messages. Unavailable/incompatible tooling or denied namespace reads returns `unavailable`; never a fabricated healthy status. Use least-privilege namespace RBAC. This adapter's command/disabled/error behavior was tested with a simulated native response; live K8sGPT is unverified.

`application_health.recovery_timeout_seconds` optionally permits 0–60 seconds of post-repair readiness polling. Zero/absent preserves existing immediate-probe behavior. The policy remains part of the approved plan's immutable health binding. Polling requires consecutive successful HTTP checks, records actual samples and elapsed time, stops after the deadline plus one bounded in-flight request, and **never repeats the repair**. Ops Pilot defaults this budget to 30 seconds and permits an explicit 1–60 second setting. A real CloudLaunch app exposed the need for this startup window: an initial restart had passed Docker state but failed early HTTP checks, and was correctly recorded `needs_attention`; the final monitored lab passed after bounded readiness support.

Shared wire contracts and the HTTP event receiver are owned by [Ops Pilot](https://github.com/Vishnu063/ops-pilot/blob/feat/unified-devops-ecosystem/docs/ecosystem/INTEGRATION.md). Triage supplies the reusable diagnostic library; no network server or AI inference starts when it is imported. Approval decisions remain backend-enforced, expiring and single-use. No rollback, deletion or production action is authorized by these integrations.

Run `python -m unittest discover -s tests -v`. Observed: 247 tests, 243 passed and four existing opt-in tests skipped; these skips are not live Docker/Kubernetes evidence. Separate Ops Pilot real-Docker and CloudLaunch/Prometheus/Jenkins acceptance evidence is recorded in its ecosystem validation document. Future work: live K8sGPT compatibility/RBAC acceptance and richer evidence-backed command objects; no arbitrary remote command API.
